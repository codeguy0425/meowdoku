v0.3 meowdoku solver

meowdoku-solver-design

A deterministic constraint-solving engine for Meowdoku — one cat per row, column, and colored region; no two cats touch (horizontally, vertically, or diagonally). The solver applies a cascade of pure-function logical rules, ordered by cheapness, with a fallback backtrack guesser.

Overview

Meowdoku is an N×N constraint puzzle. Each cell belongs to a colored region. The solver must place exactly one cat per row, per column, and per region, with no two cats adjacent. The grid is modeled as a 2D array of integers: 0 (open), 1 (cat), 2 (blocked). Regions are stored as a separate immutable 2D array of integer IDs.

Rules are implemented as pure functions scanning the grid for specific patterns. Each fires at most once per step; after any change, the next step restarts from the top of the chain. When all rules return false, the backtrack guesser selects the cell with the lowest MRV product (open in row × open in column × open in region).

Solver Chain

Each step fires exactly one rule. If it returns true, the next step restarts from the top. The chain is ordered by cheapness — fastest scans first.

0
Exclusion
When a cat is placed at (r,c): block row r, column c, region regions[r][c], and all 8 neighbors.
cost: O(N²) — 100 cells
1
Singleton
If any region, row, or column has exactly 1 open cell → place a cat there.
cost: O(N²) — 100 cells
2
Intersection
If a region's open cells are all in a single row (or column), block other regions from that row/column.
cost: O(R × N²) ≈ 1,000
3
Reverse Intersection
If a row's (or column's) open cells all belong to the same region, block that region from other rows/columns.
cost: O(N × N²) ≈ 1,000
4
Confined Group (contiguous)
If N consecutive columns (or rows) fully contain exactly N regions, those regions are locked to those columns. Block other regions from those columns.
cost: O(N² × N²) ≈ 10,000
5
Confined Group (disjoint)
Same as #4 but for any set of N columns — not necessarily consecutive. Bitmask iteration over 2^N subsets.
cost: O(2^N × N²) ≈ 102,400
6
Adjacent Pair Block (region)
If a region's remaining 2–3 open cells form a contiguous line (2×1 or 3×1), block the shared neighbor cells: 4 cells for 2×1, 2 for 3×1.
cost: O(R × N²) ≈ 1,000
7
Adjacent Pair Block (row/col)
If a row (or column) has exactly 2–3 adjacent open cells (any regions), same neighbor-blocking logic. Catches different-region pairs.
cost: O(N × N) ≈ 200
8
Adjacency Trap
For each open cell, simulate placing a cat and running exclusions. If any region would be stranded → block that cell.
cost: O(N² × R × N²) ≈ 100,000
9
Backtrack Guess
Pick cell minimizing open_in_row × open_in_col × open_in_region. Save state, place cat. On contradiction, roll back and block.
cost: O(N²) = 100

Components

grid-cell
Grid Cell

Each cell in the N×N grid. Displays region number (small, top-left), cell state icon (cat, blocked, or empty). On hover: shows tooltip with coordinates and region ID. Click: toggle cycle (open → cat → blocked → open) when in edit mode.

Color Palette Toolbar

Horizontal row of region swatches (0–9) as circular buttons. When clicked, sets the active region for grid editing. Also includes tool buttons: Inspect (view cell info), Cat (place cat), Block (place block). Active tool has highlighted border.

log-panel
Solver Log Panel

Scrolling log list showing each step's action. Each entry prefixed with [RULE: RULENAME] in a color-coded badge. Styled as a compact monospace feed with hairline separators.

control-bar
Control Bar

Row of action buttons: Step (single rule), Auto (continuous solve), Back (undo one rule), Reset (clear grid), Export JSON, Load JSON. Each is a compact pill with mono-caps label, styled on dark surface with subtle border.

json-panel
JSON Import / Export Panel

Textarea for pasting puzzle configurations (Gemini format or solver format). Auto-detects format — color-name array or numeric region IDs. Export button copies current grid state as JSON to clipboard.

Do's and Don'ts

✓ Do
  • Keep each rule as a pure scan — no shared state between rules
  • Order rules by cheapness; singleton first, adjacency trap last
  • Restart from the top after any change — cascading effects matter
  • Use MRV product heuristic for backtrack guesses
  • Display step-by-step with one rule per step for clarity
  • Auto-detect Gemini format on JSON import
✗ Don't
  • Don't nest rule calls inside each other — one rule per step
  • Don't skip singleton re-checks after a block
  • Don't use contiguous-only confined group — disjoint catches more
  • Don't let adjacent pair block starve below adjacency trap
  • Don't hardcode 9×9 — support any N up to 12
  • Don't expose cat placements that violate diagonal adjacency
