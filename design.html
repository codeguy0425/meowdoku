meowdoku-solver-design

Deterministic logical solver for Meowdoku — one cat per row, column, and colored region; no diagonal adjacency.

Overview

Meowdoku is a constraint puzzle on an N×N grid (typically 9×9 or 10×10). Each cell belongs to a colored region. The solver must place exactly one cat per row, per column, and per region, with the additional constraint that no two cats touch — horizontally, vertically, or diagonally.

The solver applies a cascade of deterministic logical rules, each implemented as a pure function that scans the grid for a specific pattern and either places a cat or blocks a cell. Rules are ordered by cheapness (fast scans first). After each rule fires, control returns to the top of the chain. When all logical rules fail to make progress, a backtracking guess is made using the Minimum Remaining Values (MRV) product heuristic.

Solver Chain

Each call to solveNextStep() fires exactly one rule. If it returns true (something changed), the next call restarts from the top. When all rules return false, backtracking triggers.

0. Exclusion (from placed cats)

When a cat is placed at (r,c): entire row r is blocked, entire column c is blocked, entire region regions[r][c] is blocked, all 8 neighbors blocked.

1. Singleton

Three independent scans: if any region / row / column has exactly 1 open cell → place a cat there.

2. Intersection

If a region's remaining open cells are all in a single row (or column), that region's cat must be in that row. All other regions are blocked from that row.

3. Reverse Intersection

If a row's (or column's) remaining open cells all belong to the same region, that region's cat must be in that row/column. Block that region from all other rows/columns.

4. Confined Group (contiguous)

If N consecutive columns (or rows) fully contain exactly N regions — no cell of those regions exists outside those columns — those N regions occupy those N columns. Block other regions from those columns.

5. Confined Group (disjoint, non-contiguous)

Same logic as #4 but for any set of N columns (not necessarily consecutive). Computed via bitmask iteration (2^N subsets, fast for N ≤ 10).

6. Adjacent Pair Block (region-based)

If a region's remaining 2–3 open cells form a contiguous 2×1 or 3×1 (horizontally or vertically), both cat placements share certain neighbors that are blocked unconditionally.

ShapeOrientationCells blocked
2×1HorizontalRow above (both cols), row below (both cols) — 4 cells
2×1VerticalLeft col (both rows), right col (both rows) — 4 cells
3×1HorizontalMiddle col, row above and below — 2 cells
3×1VerticalMiddle row, left and right col — 2 cells
7. Adjacent Pair Block (row/col-based)

If a row (or column) has exactly 2–3 adjacent open cells (any regions), same neighbor-blocking logic applies. Catches pairs the region-based check misses (different-region pairs).

8. Adjacency Trap

For each open cell, simulate placing a cat there and running basic exclusions. If any unfinished region ends up with zero open cells, that placement is impossible → block the cell.

9. Backtrack Guess

Pick the open cell minimizing open_in_row × open_in_col × open_in_region (MRV product). Save state, place a cat, continue. On contradiction, roll back, block that cell, and retry.

Rule Ordering Principles

  • Cheapest first: singleton (~100 cells) before intersection (~1K) before confined group (~10K subsets) before adjacency trap (~10K simulations)
  • Most effective first: intersection and singleton catch the majority of deductions in most puzzles
  • Restart on change: after any rule fires, the next step starts from rule 0 — handles cascading effects naturally

Most puzzles solve in 10–50 logical steps. Backtracking is rarely needed (observed only on puzzles with weak initial constraints), and when needed, typically completes within 1–3 guesses.

Architecture

Single-file implementation (index.html):

  • State: 2D array grid[N][N] where values are 0 (open), 1 (cat), 2 (blocked)
  • Regions: 2D array regions[N][N] of integer region IDs (immutable after load)
  • Rules: each is a function run*() returning boolean (true if grid was modified)
  • UI: renderGrid() redraws the board, logMessage() appends to the step log
  • Step history: stepHistory[] stores past grid states for undo
  • Backtrack stack: historyStack[] stores pre-guess snapshots for rollback

Do's and Don'ts

✓ Do
  • Keep each rule as a pure scan — no shared state between rules
  • Order rules by cheapness; singleton first, adjacency trap last
  • Restart from the top after any change — cascading effects matter
  • Use MRV product heuristic for backtrack guesses
✗ Don't
  • Don't nest rule calls inside each other — each step fires one rule
  • Don't skip singleton re-checks after a block
  • Don't use contiguous-only confined group — disjoint check is needed too
  • Don't let adjacent pair block starve below adjacency trap
