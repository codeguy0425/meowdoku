v0.3 · meowdoku solver

meowdoku-solver-design

Deterministic constraint solver — one cat per row, column, and colored region; no two cats touch (horizontally, vertically, or diagonally).

Overview

N×N grid modeled as a 2D array of integers: 0 (open), 1 (cat), 2 (blocked). Regions stored as a separate immutable 2D array of integer IDs. Rules are pure functions scanning for specific patterns. Each step fires one rule; after any change, next step restarts from the top. When all rules stall, backtrack guesser picks the cell minimizing open_in_row × open_in_col × open_in_region (MRV product).

Solver Chain

Step 0
Exclusion
When a cat is placed at (r,c): block row r, column c, entire region, and all 8 neighbors.
Step 1
Singleton
If any region, row, or column has exactly 1 open cell → place a cat there.
Step 2
Intersection
If a region's open cells are all in a single row (or column), block other regions from that row/column.
Step 3
Reverse Intersection
If a row/column's open cells all belong to the same region, block that region from other rows/columns.
Step 4
Confined Group (contiguous)
If N consecutive columns/rows fully contain exactly N regions, block other regions from those columns/rows.
Step 5
Confined Group (disjoint)
Same as Step 4 but for any set of N columns/rows (non-consecutive). Bitmask iteration over 2^N subsets.
Step 6
Adjacent Pair Block (region)
If a region's remaining 2–3 open cells form a contiguous line (2×1 or 3×1), block shared neighbor cells: 4 for 2×1, 2 for 3×1.
Step 7
Adjacent Pair Block (row/col)
If a row/column has exactly 2–3 adjacent open cells (any regions), same neighbor-blocking logic. Catches different-region pairs.
Step 8
Adjacency Trap
For each open cell, simulate placing a cat and running exclusions. If any region would be stranded → block that cell.
Step 9
Backtrack Guess
Pick cell minimizing open_in_row × open_in_col × open_in_region (MRV product). Save state, place cat. On contradiction, roll back and block.

Do's and Don'ts

✓ Do

  • Keep each rule as a pure scan — no shared state
  • Order by cheapness; singleton first, adjacency trap last
  • Restart from the top after any change
  • Use MRV product heuristic for backtrack guesses

✗ Don't

  • Don't nest rule calls — one rule per step
  • Don't skip singleton re-checks after a block
  • Don't use contiguous-only confined group — disjoint catches more
  • Don't let adjacent pair block starve below adjacency trap
